# HelpDeskPro — Release Notes v1.0.0

**Versi:** 1.0.0  
**Tanggal Rilis:** 10 November 2026  
**Target Runtime:** .NET 8 LTS (ASP.NET Core Web API + Blazor Interactive Server)  
**Database:** Microsoft SQL Server 2022  
**Arsitektur:** Clean Architecture + CQRS (MediatR) + DDD-inspired Domain Model  

---

## 1. Ringkasan Eksekutif

HelpDeskPro v1.0.0 adalah rilis perdana sistem manajemen helpdesk internal berskala enterprise. Sistem ini dirancang untuk menyederhanakan pelaporan insiden/permintaan layanan, penugasan tiket terstruktur, pemantauan batas waktu SLA real-time dengan eskalasi berjenjang otomatis, serta pengelolaan data master organisasi (Departemen, Kategori, Pengguna, dan Kebijakan SLA).

Aplikasi dibangun dengan mematuhi standar arsitektur bersih (*Clean Architecture*), prinsip SOLID, audit log otomatis, *optimistic concurrency control*, isolasi tenant/department berbasis role (Admin, Supervisor, Agent, Requester), dan antarmuka web modern berbasis MudBlazor yang mengutamakan kepadatan informasi dan efisiensi kerja pengguna.

## 2. Cakupan Fitur Terimplementasi (FR-01 s.d. FR-34)

### A. Autentikasi, Otorisasi & Pengguna (FR-01 – FR-05)
- **FR-01: Login Berbasis JWT & Identity**: Autentikasi kredensial pengguna (email/password) dengan hashing ASP.NET Core Identity dan penerbitan token JWT (HS256) dengan masa berlaku 8 jam.
- **FR-02: Role-Based Access Control (RBAC)**: Pemisahan 4 peran sistem: `Admin`, `Supervisor`, `Agent`, dan `Requester` yang ditegakkan di level API controller, MediatR handler, dan Blazor UI authorization provider.
- **FR-03: Refresh & Session Management**: Delegating handler HTTP client pada Blazor yang otomatis menyisipkan bearer token dan mengarahkan ke login jika terjadi session expiry (401).
- **FR-04: User Profiling**: Query detail profil pengguna aktif (`/api/auth/me`) untuk inisialisasi state UI.
- **FR-05: User Lifecycle & Account Lockout**: Fitur aktivasi/deaktivasi akun pengguna dengan proteksi penonaktifan supervisor sendiri dan proteksi penghapusan user yang memiliki riwayat tiket.

### B. Pengelolaan Tiket & Alur Status (FR-06 – FR-18)
- **FR-06: Pembuatan Tiket**: Formulir pelaporan tiket dengan penomoran unik otomatis berurutan tahunan (`HD-YYYY-XXXXXX`) menggunakan lock konkurensi urutan database.
- **FR-07: Penentuan Target SLA Otomatis**: Perhitungan otomatis `ResponseDueAt` dan `ResolutionDueAt` saat tiket dibuat berdasarkan matriks prioritas (Critical: 15m/2h, High: 30m/4h, Medium: 1h/8h, Low: 2h/24h).
- **FR-08: Daftar Tiket Terfilter & Paging**: Server-side pagination (20/50/100 baris) dengan filter multi-status, multi-prioritas, kategori, assignee, dan pencarian teks.
- **FR-09: Isolasi Tiket Berdasarkan Role**:
  - Requester hanya melihat tiket yang dibuatnya.
  - Agent melihat tiket yang ditugaskan kepadanya atau yang belum memiliki assignee (unassigned pool).
  - Supervisor IT melihat seluruh tiket; Supervisor non-IT hanya melihat tiket departemennya.
  - Admin memiliki akses penuh ke seluruh tiket.
- **FR-10: Pengambilan Mandiri Tiket (Self-Assign)**: Agent dapat mengklaim tiket yang belum memiliki penugasan dengan satu klik.
- **FR-11: Penugasan Tiket (Assign by Supervisor/Admin)**: Supervisor dan Admin dapat menugaskan atau mengalihkan penugasan tiket ke Agent tertentu.
- **FR-12: Transisi Status Tiket**: Penegakan alur status ketat (New → InProgress → Pending → Resolved → Closed / Cancelled) melalui metode domain `Ticket`.
- **FR-13: Status Pending & SLA Pause**: Transisi status ke `Pending` otomatis menghentikan sementara perhitungan countdown SLA dan mencatat akumulasi waktu jeda (`TotalPausedMinutes`).
- **FR-14: Resolusi Tiket**: Pencatatan tanggal resolusi (`ResolvedAt`) dan verifikasi status pemenuhan SLA.
- **FR-15: Penutupan & Pembatalan Tiket**: Tiket berstatus `Resolved` dapat ditutup final (`Closed`) atau dibatalkan (`Cancelled`) dengan catatan alasan wajib.
- **FR-16: Pembukaan Kembali (Reopen)**: Tiket `Resolved` dapat dibuka kembali ke `InProgress` jika solusi belum memuaskan.
- **FR-17: Optimistic Concurrency Control**: Kolom `RowVersion` pada entitas tiket untuk mendeteksi konflik penyuntingan simultan (menghasilkan status HTTP 409 Conflict dengan dialog muat ulang di UI).
- **FR-18: Riwayat Audit Tiket (Audit Trail)**: Setiap perubahan status, assignee, prioritas, dan data tiket otomatis dicatat dalam `TicketHistories` dengan identitas pelaku dan stempel waktu UTC.

### C. Kolaborasi, Komentar & Lampiran (FR-19 – FR-22)
- **FR-19: Komentar Publik & Internal**: Penambahan catatan pada tiket dengan toggle "Internal Note" (hanya terlihat oleh Agent, Supervisor, dan Admin; disembunyikan total dari Requester).
- **FR-20: Timeline Terpadu**: Tampilan kronologis gabungan antara riwayat audit sistem dan komentar diskusi pengguna.
- **FR-21: Unggah Lampiran (Attachments)**: Validasi tipe file aman (`.jpg`, `.jpeg`, `.png`, `.pdf`, `.docx`, `.xlsx`, `.zip`) dengan batas ukuran maksimal 5 MB per file.
- **FR-22: Unduh Lampiran Aman**: Endpoint unduh file terautentikasi dengan verifikasi hak akses tiket.

### D. SLA Engine, Background Monitoring & Notifikasi (FR-23 – FR-28)
- **FR-23: SLA Countdown Display**: Komponen hitung mundur waktu SLA visual dengan peringatan warna merah saat breached dan status jeda saat pending.
- **FR-24: SlaMonitorService (Background Worker)**: Background service berkala (interval 60 detik) yang memindai tiket aktif mendekati batas SLA atau yang telah terlampaui.
- **FR-25: Eskalasi Otomatis Bertingkat**:
  - Level 1: Peringatan ke Agent saat tersisa $\le 30$ menit.
  - Level 2: Notifikasi eskalasi ke Supervisor saat SLA terlampaui.
  - Level 3: Notifikasi eskalasi ke Admin/Management jika belum terselesaikan dalam toleransi lanjutan.
- **FR-26: Pengakuan Eskalasi (Acknowledge)**: Fitur bagi Supervisor/Admin untuk menandai eskalasi telah ditindaklanjuti.
- **FR-27: Sistem Notifikasi Dalam Aplikasi**: Notifikasi in-app untuk penugasan, komentar baru, perubahan status, dan eskalasi.
- **FR-28: Panel Popover Notifikasi**: Indikator lonceng dengan unread count, popover 10 notifikasi terbaru, aksi tandai dibaca, dan halaman riwayat lengkap.

### E. Dashboard Eksekutif & Manajemen Master Data (FR-29 – FR-34)
- **FR-29: Dashboard Metrik Operasional**: Ringkasan jumlah tiket (Total, Terbuka, Lewat SLA, Rata-rata Resolusi), tabel beban kerja per agen, dan daftar eskalasi aktif.
- **FR-30: Grafik Tren Tiket**: Visualisasi grafik batang harian tiket masuk vs tiket terselesaikan (MudChart).
- **FR-31: Manajemen Departemen**: CRUD data departemen dengan kode unik dan validasi relasi pengguna aktif.
- **FR-32: Manajemen Kategori**: CRUD kategori tiket dengan indikator penggunaan pada tiket aktif.
- **FR-33: Manajemen Pengguna & Reset Password**: Pembuatan user, pengaturan role, penugasan departemen & supervisor, reset password aman, dan toggle status aktif.
- **FR-34: Manajemen Kebijakan SLA**: Konfigurasi dinamis target waktu respon dan resolusi untuk setiap tingkat prioritas.

## 4. Known Issues & Catatan Operasional

1. **Local File Storage Default**:
   - Implementasi `IFileStorage` saat ini menggunakan direktori penyimpanan berkas lokal (`uploads/tickets`).
   - *Rekomendasi untuk lingkungan multi-node/Kubernetes*: Ganti implementasi `IFileStorage` dengan Azure Blob Storage atau Amazon S3 / MinIO.
2. **MudBlazor Chart Rendering**:
   - Grafik batang pada halaman dashboard mengandalkan dimensi viewport klien. Pada layar mobile dengan lebar $< 400\text{px}$, grafik ditampilkan secara horizontal-scroll.
3. **Penyimpanan State Filter di Blazor**:
   - Filter daftar tiket disimpan di `localStorage` per peramban pengguna. Menghapus *cache/storage* peramban akan mengembalikan filter ke nilai default.

## 5. Panduan Deployment

### A. Persyaratan Lingkungan
- **.NET Runtime**: .NET 8.0 ASP.NET Core Runtime (atau .NET 8.0 SDK untuk kompilasi dari sumber).
- **Database Engine**: Microsoft SQL Server 2019+ atau Azure SQL Database.
- **Port Default**:
  - Web API: `http://localhost:5017`
  - Blazor Web UI: `http://localhost:5247`

### B. Konfigurasi Environment Variables

Gunakan environment variables atau User Secrets pada lingkungan produksi untuk menimpa nilai default:

| Variabel | Deskripsi | Contoh Nilai Produksi |
|---|---|---|
| `ConnectionStrings__DefaultConnection` | String koneksi database SQL Server | `Server=sql.prod.internal;Database=HelpDeskProDb;User Id=helpdesk_user;Password=...;TrustServerCertificate=False;` |
| `JwtSettings__SecretKey` | Kunci simetris penandatanganan JWT (min. 32 karakter) | *Generate string acak aman $\ge 256$ bit* |
| `JwtSettings__Issuer` | Penerbit token JWT | `https://api.helpdesk.perusahaan.com` |
| `JwtSettings__Audience` | Audiens target JWT | `https://helpdesk.perusahaan.com` |
| `ApiSettings__BaseUrl` | URL API yang diakses oleh Blazor UI | `https://api.helpdesk.perusahaan.com` |
| `ASPNETCORE_ENVIRONMENT` | Profil lingkungan ASP.NET Core | `Production` |

### C. Langkah Deployment via Docker Compose

1. Clone repositori pada server tujuan:
   ```bash
   git clone <repository-url>
   cd HelpDeskPro-Antigravity
   ```

2. Siapkan file `.env` produksi:
   ```env
   SA_PASSWORD=SuperSecurePass2026!
   JWT_SECRET=ProdSecretKeyWithSufficientEntropyAndLength2026!
   ```

3. Jalankan container:
   ```bash
   docker compose up -d
   ```

4. Database migration dan seeding awal akun administrator akan dieksekusi secara otomatis saat API pertama kali dijalankan.
